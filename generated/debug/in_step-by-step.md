# Пошаговое описание бизнес-процесса CRM системы НКО

## 1. Общее описание процесса

Бизнес-процесс охватывает управление документами и информацией о физических лицах (ФЛ) в CRM-системе НКО. Процесс включает регистрацию новых ФЛ, создание персональных папок и кабинетов, управление документами, работу с реестрами и предоставление доступа к информации.

## 2. Участники процесса

### 2.1 Физическое лицо (ФЛ)
- Основной пользователь системы
- Имеет личный кабинет на сайте НКО
- Может загружать и скачивать свои документы
- Получает уведомления о новых документах

### 2.2 Администратор НКО
- Управляет данными клиентов и ФЛ
- Создает/обновляет реестры ФЛ
- Применяет фильтрацию и сортировку к реестрам
- Управляет правами доступа

### 2.3 Система
- Автоматически создает персональные папки и кабинеты
- Обрабатывает загрузку и скачивание документов
- Обновляет реестры при изменении данных
- Выполняет проверку авторизации
- Отправляет уведомления

## 3. Последовательность шагов процесса

### 3.1 Начало процесса
1. Система ожидает регистрации нового ФЛ
2. ФЛ обращается к системе для регистрации
3. Система отображает форму регистрации для ФЛ

### 3.2 Регистрация нового ФЛ
1. ФЛ заполняет регистрационную форму
2. Система проверяет корректность введенных данных
   - Возможные варианты:
     - Данные корректны → продолжить регистрацию
     - Данные некорректны → отобразить ошибку и запросить повторный ввод
3. Система создает запись о новом ФЛ в базе данных
4. Система автоматически создает персональную папку для ФЛ
5. Система автоматически создает личный кабинет для ФЛ
6. Система отображает сообщение об успешной регистрации и предлагает перейти к личному кабинету

### 3.3 Управление документами
1. ФЛ может загружать документы в свою персональную папку
2. Система проверяет тип и формат документа
   - Возможные варианты:
     - Документ допустимого типа → продолжить загрузку
     - Документ недопустимого типа → отобразить ошибку
3. Система сохраняет документ в персональной папке ФЛ
4. Система обновляет реестр ФЛ с информацией о новых документах
5. Система может отправлять уведомления о новых документах
   - Возможные варианты:
     - Уведомления включены → отправить уведомление
     - Уведомления выключены → не отправлять уведомление

### 3.4 Работа с реестрами
1. Администратор НКО обращается к реестру ФЛ
2. Система отображает список всех ФЛ с основными атрибутами
3. Администратор может применять фильтры по различным атрибутам
   - Возможные варианты:
     - Фильтры применены → отобразить отфильтрованный список
     - Фильтры не применены → отобразить полный список
4. Администратор может сортировать список по заданным параметрам
   - Возможные варианты:
     - Сортировка применена → отобразить отсортированный список
     - Сортировка не применена → отобразить неотсортированный список
5. Система отображает отфильтрованный/отсортированный список

### 3.5 Доступ к личному кабинету
1. ФЛ обращается к личному кабинету через сайт НКО
2. Система проверяет авторизацию пользователя
   - Возможные варианты:
     - Авторизация успешна → продолжить вход
     - Авторизация неуспешна → отобразить ошибку и запросить повторный вход
3. Система открывает личный кабинет ФЛ
4. Система отображает информацию о ФЛ:
   - Основные данные (ФИО, email, телефон и т.д.)
   - Статус учетной записи
   - Количество документов в папке
5. Система отображает связанные с ФЛ документы:
   - Список документов с возможностью просмотра/скачивания
   - Дата создания/обновления документов
   - Размер файлов

### 3.6 Скачивание документов
1. ФЛ выбирает документы для скачивания
2. Система проверяет права доступа к выбранным документам
   - Возможные варианты:
     - Доступ разрешен → продолжить скачивание
     - Доступ запрещен → отобразить ошибку доступа
3. Система предоставляет возможность скачивания
   - Возможные варианты:
     - Скачивание одного документа → отобразить кнопку скачивания
     - Скачивание группы документов → создать архив и отобразить ссылку на скачивание
4. Система обновляет историю действий пользователя
   - Записывает дату, тип действия и список скачанных документов

### 3.7 Завершение процесса
1. Все операции завершены
2. Система может отправлять уведомления при необходимости
   - Возможные варианты:
     - Уведомления включены → отправить уведомление
     - Уведомления выключены → не отправлять уведомление
3. Процесс завершается

## 4. Условия и принятие решений

### 4.1 Загрузка документов
- Если ФЛ загружает документы → переходит к обновлению реестра
- Если ФЛ не загружает документы → продолжает обновление реестра

### 4.2 Фильтрация/сортировка
- Если требуется фильтрация/сортировка → применяется фильтрация/сортировка
- Если фильтрация/сортировка не требуется → отображается полный реестр

### 4.3 Доступ к кабинету
- Если ФЛ запрашивает доступ к кабинету → проверка авторизации
- Если ФЛ не запрашивает доступ → процесс завершается

### 4.4 Скачивание документов
- Если ФЛ скачивает документы → проверка прав доступа
- Если ФЛ не скачивает документы → завершение процесса

### 4.5 Уведомления
- Если нужны уведомления → отправка уведомления
- Если уведомления не требуются → завершение процесса

## 5. Технические требования

### 5.1 Безопасность
- Все персональные данные шифруются при хранении
- Доступ к данным ограничен по роли пользователя
- Система проверяет права доступа перед каждой операцией

### 5.2 Производительность
- Система должна работать стабильно с большим количеством ФЛ
- Загрузка и отображение данных происходит быстро
- Производительность не падает с увеличением объема данных

### 5.3 Интерфейс
- Интерфейс администратора и пользователей должен быть удобным
- Система соответствует стандартам веб-разработки
