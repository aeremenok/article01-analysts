# Требования к системе CRM

## 1. Stakeholders (роли пользователей)

- **Администратор** — пользователь, который управляет системой, формирует реестры и управляет документами
  - Основные задачи: управление папками физических лиц, хранение документов, формирование реестров
  - Боли: Необходимость ручной работы с документами, сложность фильтрации и сортировки
  - Ожидания: Автоматизация процессов, удобный интерфейс для работы с данными
  - Уровень доступа: Полный доступ к данным, возможность управления реестрами

- **Пользователь (физическое лицо)** — человек, у которого есть личный кабинет на сайте организации
  - Основные задачи: доступ к личному кабинету, взаимодействие с системой через сайт
  - Боли: Необходимость наличия личного кабинета для доступа к информации
  - Ожидания: Удобный доступ к личным данным через интернет
  - Уровень доступа: Ограниченный доступ к своим данным

## 2. Текущая ситуация (AS-IS)

### 2.1 Существующий процесс
1. Для каждого физического лица создается папка
2. В папке хранятся документы, включая персональные данные (ПД)
3. Из физических лиц формируется реестр с возможностью фильтрации, сортировки и выборки по атрибутам
4. У каждого физического лица должен быть личный кабинет на сайте организации (НКО)
5. Система должна обеспечивать хранение и управление персональными данными

### 2.2 Проблемы текущего процесса
- 🔴 **Критичные**: 
  - Сложность ручного управления папками и документами для каждого физического лица
  - Отсутствие автоматизированного реестра с возможностью фильтрации и сортировки
- 🟡 **Важные**: 
  - Необходимость наличия личного кабинета для каждого физического лица
  - Необходимость хранения и управления персональными данными
- 🟢 **Желательные к устранению**: 
  - Потенциальная необходимость улучшения интерфейса для удобства работы

### 2.3 Технический контекст
- Используемые системы: Физические папки, сайт НКО
- Интеграции: Сайт организации (НКО) с системой хранения данных
- Объемы: Не указано конкретных данных, но предполагается наличие большого количества физических лиц

## 3. Функциональные требования

### 3.1 Управление данными физических лиц

- **FR-001**: Система должна позволять администратору создавать и управлять папками для физических лиц
  - Источник: "нужно сделать CRM"
  - Приоритет: Must
  - Уверенность: 🎯 Явное

- **FR-002**: Система должна позволять администратору хранить документы в папках физических лиц
  - Источник: "на каждое физлицо есть папка, где хранятся документы, в том числе с ПД"
  - Приоритет: Must
  - Уверенность: 🎯 Явное

- **FR-003**: Система должна позволять администратору формировать реестры физических лиц с фильтрацией, сортировкой и выборкой по атрибутам
  - Источник: "из этих физлиц нужно формировать реестр (фильтрация, сортировка, выборка по атрибутам)"
  - Приоритет: Must
  - Уверенность: 🎯 Явное

### 3.2 Личный кабинет физического лица

- **FR-004**: Система должна предоставлять личный кабинет для каждого физического лица на сайте организации
  - Источник: "у каждого ФЛ должен быть личный кабинет на сайте организации (НКО)"
  - Приоритет: Must
  - Уверенность: 🎯 Явное

- **FR-005**: Система должна обеспечивать доступ к личным данным через личный кабинет
  - Источник: "у каждого ФЛ должен быть личный кабинет на сайте организации (НКО)"
  - Приоритет: Must
  - Уверенность: 💡 Выведено (80%)

### 3.3 Хранение персональных данных

- **FR-006**: Система должна обеспечивать хранение персональных данных физических лиц
  - Источник: "на каждое физлицо есть папка, где хранятся документы, в том числе с ПД"
  - Приоритет: Must
  - Уверенность: 🎯 Явное

## 4. Нефункциональные требования

### 4.1 Безопасность
- **NFR-S-001**: Система должна обеспечивать защиту персональных данных в соответствии с законодательством РФ
  - Метрика: Соответствие требованиям 152-ФЗ
  - Источник: "на каждое физлицо есть папка, где хранятся документы, в том числе с ПД" 💡 Выведено из контекста

### 4.2 Производительность
- Требования к производительности не уточняются явно, но предполагается, что система должна обрабатывать запросы пользователей в разумные сроки

### 4.3 Доступность
- Система должна быть доступна через интернет, особенно личный кабинет физических лиц

### 4.4 Совместимость
- Система должна быть совместима с современными браузерами и устройствами для доступа к личному кабинету

### 4.5 Масштабируемость
- Система должна поддерживать рост числа физических лиц и объема данных

## 5. Ограничения

### 5.1 Технические
- Система должна быть интегрирована с сайтом организации (НКО)
- Использование существующей инфраструктуры сайта

### 5.2 Организационные
- Не указаны конкретные сроки или состав команды

### 5.3 Регуляторные
- Соблюдение требований законодательства РФ в части защиты персональных данных (152-ФЗ)

### 5.4 Бюджетные
- Не указаны бюджетные ограничения

## 6. Предположения

- В системе будут храниться персональные данные физических лиц, поэтому необходимо соблюдать требования законодательства РФ (152-ФЗ) — уверенность 80%, основание: Упоминание ПД (персональные данные) и необходимости их защиты
- Пользователи могут иметь разный уровень доступа к данным, в зависимости от роли — уверенность 60%, основание: Наличие администратора и пользователей

## 8. Словарь терминов

- **CRM**: Система управления взаимоотношениями с клиентами
- **ФЛ**: Физическое лицо
- **ПД**: Персональные данные
- **НКО**: Некоммерческая организация
