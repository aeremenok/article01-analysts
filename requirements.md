# Структурированные Требования

## 1. Stakeholders (Роли Пользователей)
- Физические лица (ФЛ): конечные пользователи системы, имеющие личные кабинеты.
- Администраторы: сотрудники НКО, управляющие данными и системой.
- Клиенты: заказчики или спонсоры проекта.

## 2. Текущая Ситуация (AS-IS)
В настоящее время данные о физических лицах хранятся в отдельных папках, содержащих различные документы, включая персональные данные (ПД). Эти данные используются для формирования реестров вручную через фильтрацию, сортировку и выборку по атрибутам.

## 3. Функциональные Требования
### Категории Функций
- Управление данными: хранение документов и персональных данных.
- Личный Кабинет: доступ к информации для каждого физического лица.
- Формирование Реестра: фильтрация, сортировка и выборка по атрибутам.
- Безопасность: защита персональных данных согласно законодательству РФ.

## 4. Нефункциональные Требования
- Производительность: система должна обеспечивать быстрый доступ к данным без задержек.
- Масштабируемость: возможность расширения базы данных при увеличении числа пользователей.
- Удобство использования: интуитивно понятный интерфейс личного кабинета.
- Соответствие нормативным требованиям: соблюдение законодательства РФ о защите персональных данных.

## 5. Ограничения
- Регулирование: необходимость соблюдения законов РФ о защите персональных данных.
- Технические ограничения: использование существующих систем хранения данных.
