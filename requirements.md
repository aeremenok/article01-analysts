# Требования к системе CRM

## 1. Stakeholders (роли пользователей)

- **Клиент** (заказчик): Ответственный за проект, определяет бизнес-требования
- **Физические лица (ФЛ)**: Конечные пользователи системы, которым необходим личный кабинет на сайте организации (НКО)
- **Администраторы CRM**: Ответственные за управление данными, включая добавление/редактирование информации о физических лицах и документах
- **Сотрудники НКО**: Пользователи системы, осуществляющие фильтрацию, сортировку и выборку данных для формирования реестров

## 2. Текущая ситуация (AS-IS)

- Существует необходимость в создании системы управления отношениями с клиентами (CRM) для НКО
- У каждого физического лица должна быть своя папка для хранения документов
- Документы могут содержать персональные данные (ПД)
- Необходимо иметь возможность формировать реестры на основе данных физических лиц
- Реестры должны поддерживать фильтрацию, сортировку и выборку по различным атрибутам
- Каждому физическому лицу должен быть предоставлен личный кабинет на сайте организации

## 3. Функциональные требования (по категориям)

### 3.1 Управление данными физических лиц
- Создание и редактирование информации о физических лицах
- Назначение персональной папки для каждого физического лица
- Хранение документов в персональных папках физических лиц
- Обеспечение безопасности хранения персональных данных

### 3.2 Формирование реестров
- Формирование реестров на основе данных физических лиц
- Фильтрация данных по различным атрибутам
- Сортировка данных в реестрах
- Выборка данных из реестров по заданным критериям

### 3.3 Личный кабинет физического лица
- Предоставление доступа к личному кабинету на сайте организации
- Возможность просмотра и управления своими данными
- Доступ к документам в собственной папке

## 4. Нефункциональные требования

- **Безопасность**
  - Обеспечение защиты персональных данных в соответствии с законодательством
  - Развитие механизмы аутентификации и авторизации пользователей
  - Контроль доступа к данным физических лиц
  
- **Производительность**
  - Быстрая загрузка данных при формировании реестров
  - Эффективная работа с большими объемами документов
  
- **Доступность**
  - Обеспечение работы системы в режиме онлайн
  - Поддержка мобильных устройств и различных браузеров
  
- **Поддержка**
  - Возможность масштабирования системы при увеличении числа пользователей
  - Интеграция с существующими системами НКО

## 5. Ограничения

- **Технические ограничения**
  - Система должна быть разработана с учетом возможностей существующей IT-инфраструктуры НКО
  - Необходимо обеспечить совместимость с текущими системами учета и документооборота
  
- **Организационные ограничения**
  - Ограниченный срок реализации проекта
  - Ограниченный бюджет для разработки и внедрения системы
